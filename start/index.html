Обучение Git для начинающих с нуля

Изучите основы Git с нуля: установка и настройка, первый репозиторий и коммит, базовые принципы работы. Пошаговое обучение Git для начинающих на GitStart.

Этот маршрут ведёт от установки Git до первого сохранённого изменения. Чтобы пройти его, достаточно текстового редактора, терминала и отдельной папки для примеров. Открывайте уроки по порядку или переходите прямо к шагу, который нужен сейчас. Если инструмент уже установлен, начните с настройки имени автора.

Обучение Git проще, когда каждый шаг заканчивается проверкой. Повторите действия в отдельной папке: создайте текстовый файл и посмотрите, как меняется вывод статуса до и после добавления в индекс. Если результат отличается от примера, проверьте, в какой папке открыт терминал и тот ли файл добавлен. Так вы освоите основы Git на собственных изменениях и сможете повторить действия в рабочем проекте.

Что такое Git и зачем он нужен

Git хранит историю проекта в виде коммитов. Коммит — это сохранённый снимок подготовленных изменений с коротким сообщением. По истории можно понять, что изменилось, сравнить версии файла и найти момент, когда появилась ошибка. Для первых коммитов не нужен сервер: они остаются на вашем компьютере.

Разобраться, как устроен Git

Установка Git

Выберите способ установки для Windows, macOS или Linux. После установки откройте новое окно терминала и выполните git --version. Если появляется номер версии, можно продолжать. В Windows для наших упражнений с созданием файлов удобен Git Bash, хотя сами команды Git работают и в PowerShell.

Открыть инструкцию по установке Git

Первоначальная настройка Git

Перед первым коммитом укажите имя и адрес электронной почты. Эти данные войдут в историю, поэтому заранее решите, какой адрес готовы показывать в публичном проекте. Для всех проектов можно задать общие значения, а для отдельного репозитория — локальные.

Настроить имя и адрес через git config

Первый Git-репозиторий

Создайте отдельную папку и запустите в ней git init. Так вы получите учебный репозиторий, в котором можно безопасно повторять примеры. Git создаст служебную папку .git с настройками и будущей историей. Сами рабочие файлы останутся в обычной папке.

Создание репозитория и проверка состояния

После инициализации запустите git status и убедитесь, что открыли нужный проект. Создайте небольшой README.md с описанием. В статусе он сначала появится как неотслеживаемый файл.

Создать первый репозиторий

Первый коммит

У файла есть три состояния, которые важно различать: текущая версия в рабочей папке, подготовленный снимок в индексе и сохранённая версия в истории. Добавление в индекс ещё не создаёт коммит. Благодаря этому можно проверить, какие именно правки попадут в историю.

Добавление файлов и фиксация изменений

Подготовьте README через git add, проверьте состояние и сохраните его с понятным сообщением через git commit. После коммита посмотрите историю. Если других изменений нет, сокращённый статус будет пустым.

Сделать первый коммит

Что изучать дальше

Когда первый коммит готов, пройдите один пример целиком. В нём вы добавите заметку в отдельной ветке, объедините изменения с основной веткой и посмотрите историю. Публикацию на GitHub можно оставить на потом: базовые шаги выполняются локально.

Ветки, удалённые репозитории и GitHub

Ветки помогают разрабатывать изменения отдельно. Удалённые репозитории позволяют обмениваться коммитами, а GitHub даёт место для совместной работы. Если нужно быстро вспомнить синтаксис, откройте шпаргалку; за короткими пояснениями загляните в частые вопросы.
